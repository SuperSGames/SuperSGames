# SuperSGames UI.md — 현재 적용 핵심 규칙 v4.0 (경량 원본)

> **사용 범위:** 모든 기존·신규 SuperSGames 게임의 UI 제작·에셋 교체·연동. **원칙:** 사용자 승인된 최신 원화·레이아웃·기능·터치·게임 데이터를 보존한다. 상세 원본은 [UI v4 전체 원문 아카이브](archive/UI_v4_full_before_context_cleanup_2026-11-15.md). 이전 v1~v3 중 충돌하는 예시와 방대한 이미지 생성 프롬프트는 현재 지시가 아니다.

## 1. 실제 필요한 UI만 제작

1. 작업 전 해당 게임의 실제 소스, 최신 완성본, 승인 이미지, 메인/HUD/설정/상점/미션/결과/광고/튜토리얼/하단 바의 모든 클릭 요소를 조사한다. **게임에 없는 버튼은 상상해서 만들지 않고**, 존재하는 버튼을 누락하지 않는다.
2. 기능별 독립 에셋·아이콘·라벨·이벤트·표시 조건을 유지한다. 같은 빈 버튼판 원화의 재사용은 가능하지만 서로 다른 버튼의 기능을 합치지 않는다. 기존 정상 UI와 사용자 지정 원화를 요청 없이 교체하지 않는다.
3. 메인 버튼은 실제 사용 크기에서 읽히고 터치하기 편하게 만든다. 비율이 다른 큰 판/막대/창을 정사각형 셀에 무리하게 끼워 찌그러뜨리지 않는다. 기존 게임별 고정 좌표·버튼 크기·터치 영역을 보존한다.

## 2. 모든 클릭 버튼의 상태별 원화 필수

| 요소 | 필수 원화 | 조건부 상태 |
|---|---|---|
| 시작·힌트·섞기·재시작·홈·다음·닫기 X·뒤로·+·광고·구매 등 클릭 버튼 | **버튼마다 normal + pressed** | disabled/locked |
| 하단·메뉴 탭 | **탭마다 normal + pressed + selected** | selected_pressed/disabled |
| ON/OFF 스위치 | **OFF normal/pressed + ON normal/pressed = 4개** | disabled |
| 비클릭 배경/판/장식 | 고정 원화 1개 | 클릭 기능이 새로 생길 때 위 기준 |

- **pressed는 별도로 실제 그린 래스터 원화**여야 한다. 기존 normal을 CSS opacity/scale/색 바꾸기로만 처리하여 신규 아트의 pressed 제작을 생략하지 않는다.
- normal/pressed는 같은 캔버스·앵커·크기·터치 판정을 공유하며 눌린 깊이·광원으로 구별한다.
- 버튼판과 기능 고정 아이콘도 가능한 별도 에셋/레이어로 구분한다. 클릭/눌림/취소 이벤트와 선택/비활성 복귀 상태를 독립 관리하여 보상·결제 중복 실행을 피한다.

## 3. 가변 정보는 절대 원화에 굽지 않음

- 숫자·보유수량·가격·점수·레벨·스테이지·시간·남은 이동·HP·게이지 채움·알림 점/느낌표/NEW·선택·잠금·완료 및 조건부 문구는 **게임 코드의 분리된 텍스트/상태 레이어**가 표시·갱신한다.
- 기본적으로 버튼명과 글씨도 이미지 원화에 넣지 않는다. 고정 로고처럼 사용자가 명시 승인한 예외만 허용한다.
- 팝업을 통째로 합성한 한 장 그림으로 만들지 않는다. **배경 → 창·판 → 빈 슬롯 → 상태별 버튼판 → 고정 의미 아이콘/장식 → 코드 텍스트·수치 → 조건부 알림·이펙트**로 분리한다. 필요한 오브젝트는 독립 이미지로 게임에서만 조립한다.

## 4. 그림 구현 방식

- **SVG 파일·inline SVG·SVG 경로로 캐릭터/버튼/아이콘/장식/배경을 제작하지 않는다.** SVG를 PNG로 변환하는 우회도 금지한다.
- CSS 사각형·원·그라디언트·가상 요소·shadow·clip-path, Canvas 도형/경로, 텍스트 이모지로 그림을 조립하지 않는다. **이미 실제 제작한 PNG/WebP 원화 또는 새로 그린 래스터 이미지**를 쓴다.
- CSS/HTML/Canvas는 레이아웃·텍스트·입력 판정·기존 동작 기능에만 사용 가능. **기존 정상 코드를 문서 정리만을 이유로 제거하지 않는다.**
- 사용자 승인 원화를 우선하며 원본 아트의 색·형태·규격·버튼 이름·버튼 간 간격을 요청 없이 바꾸지 않는다.

## 5. 투명 PNG 스프라이트: 실픽셀 검증 필수

1. R행×C열, 기본 **셀 256×256px**(사용자가 다른 크기 지정 시 그 값), 전체 크기는 **(C×셀너비)×(R×셀높이)** 정수 px. 한 칸에는 오직 **한 개 요소의 한 상태**만 둔다.
2. 최종 파일 **PNG RGBA**, 전체 배경 alpha=0. 모든 셀 상·하·좌·우 **외곽 2px의 모든 픽셀 alpha는 정확히 0**. 격자선·분할선·테두리·반투명 배경·잔여 픽셀을 금지한다.
3. 그림의 꼬리·귀·손가락·빛·그림자·이펙트도 자기 셀 안쪽에만 존재하며 인접 셀 침범·겹침·잘림은 0이어야 한다.
4. **생성 모델 출력을 그대로 신뢰하지 않는다.** 최종 이미지를 실제 픽셀로 확인하고 필요 시 재배치·정규화한다. 모든 셀의 알파 경계를 검증하지 못하면 완료라 보고하지 않는다.
5. 여러 출력 시트를 요구하지 않는 한 최종 이미지 시트 1장을 제공한다. 기능상 반드시 다른 비율의 원화가 필요한 경우 요청한 납품 형식을 우선한다.

## 6. 실제 게임 연결 및 화면

- 공통 모바일 논리 화면 **414×896**. 기존 게임 좌표를 유지하며 최상위 게임 컨테이너만 `s = min(1, viewportWidth / 414, viewportHeight / 896)`로 **균일 축소**한다. 1배 초과 확대·세로만 압축·내부 요소별 미디어쿼리 확대는 금지한다. 세로/가로별 차이, 삼성 펀치홀, 하단바 위치, 탭 selected 위치를 확인한다.
- 화면과 입력의 원점·정렬·스케일 변경은 실제 기존 코드를 살펴보고 최소 변경한다. 앱 전환, 회전, resize, pageshow, 웹뷰, 터치 캔슬·포인터 이탈을 점검한다.
- 신규 에셋을 게임에 적용하라는 요청일 때만 최신 소스의 실제 참조 경로를 수정한다. UI 그림만 요청받은 경우 코드·웹배포 변경은 하지 않는다.

## 7. 검수와 완료 판정

- 버튼 목록/상태/이름, 원화 시트/픽셀/RGBA, 누락·잘림, 사용자 승인 원화 일치, 텍스트 레이어, 상태별 실제 클릭 기능을 확인한다.
- **이미지 생성 / 픽셀 검사 / 소스 정적 검사 / 브라우저 동작 / 실기기 테스트 / GitHub 저장 / Cloudflare 배포 / 실제 테스트웹 반영**은 서로 다른 작업이다. 실행하지 않은 단계를 성공했다고 말하지 않는다.
- 충돌하는 과거 규칙은 [아카이브](archive/UI_v4_full_before_context_cleanup_2026-11-15.md)에서 역사 자료로 확인한다. **새 작업에는 현재 이 문서와 사용자의 최신 명시적 지시가 우선**한다.
