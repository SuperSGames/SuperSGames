# Cloudflare 테스트웹 배포 공통 규칙 (2026-11-14)

**대상:** SuperSGames의 모든 기존·신규 게임. 사용자가 게임 코드·UI·아트·밸런스를 수정하거나 제작하라고 하면 기본 결과물은 파일만이 아니라 **기존 공식 Cloudflare 테스트웹에 실제로 반영된 게임**이다. 단순 MD/기획 수정은 실웹 배포를 뜻하지 않는다.

## 배포 시작 전 필수 확인
1. 해당 프로젝트의 **실제 최신 원본**, GitHub 저장소·브랜치·HEAD SHA, 배포 대상 URL을 확인한다. 이전 HTML·다른 게임 워커를 사용하지 않는다.
2. `wrangler.toml/jsonc`, 기존 배포 스크립트/워크플로, Worker 이름, 소스·출력 경로, Git 연동·production 브랜치·빌드/배포 명령을 확인한다. Cloudflare 대시보드 접근 없이 연동 상태를 추측하지 않는다.
3. 기존 정상 **GitHub → Cloudflare Workers Builds** 자동배포가 있으면 최우선 이용한다. GitHub가 이미 연결되어 있으면 이유 없이 별도 Cloudflare 브라우저 로그인을 요구하지 않는다. 기존 연결을 확인하지 않고 새 GitHub Actions, 토큰 방식, 다른 사이트를 만들거나 기존 설정을 덮어쓰지 않는다.
4. 사용자 지정 게임별 원본·UI·버튼·저장·광고·결제·랭킹 및 정식 서비스 배포를 보존한다. 요청 사항만 최소 변경한다.

## 변경부터 실제 테스트웹까지 필수 순서
1. 실제 배포 입력 소스와 참조 에셋을 수정한다. **편집한 파일이 빌드 출력물에 들어가는지** 확인한다.
2. 문법·에셋 파일 존재·참조 경로·이벤트 동작을 검사한다. 실행 환경이 있으면 기존 빌드 명령으로 빌드하고 `index.html`·필수 에셋을 확인한다. 빌드 실패를 성공으로 취급하지 않는다.
3. 올바른 저장소 `main`에 커밋하고 **커밋 SHA**를 기록한다. GitHub 커밋 성공은 웹 배포 성공이 아니다.
4. **해당 Cloudflare Worker**의 Builds/Deployments 로그 또는 승인된 배포 상태로 실제 배포 성공·연결 SHA·Worker명을 확인한다. 단순 HTTP 200 응답으로 새 배포라고 단정하지 않는다.
5. 고정 공개 테스트 URL에서 **새로 수정한 화면/에셋/게임 동작**을 실제로 확인한다. 캐시 오인을 피하려면 고유 쿼리 파라미터, 에셋 경로·내용, Service Worker 업데이트 등을 점검한다. 가능하면 모바일 실기기 동작까지 확인하고 검증 범위를 명시한다.
6. 보고에는 반드시 **저장소 / 브랜치·SHA / 빌드 성공 여부 / Cloudflare 배포 확인 여부 / 실웹 새 내용 확인 여부 / 공식 테스트 URL / 미검증 사항**을 포함한다.

## 오류별 복구
- **GitHub만 바뀜:** Cloudflare Git 저장소·브랜치·빌드 트리거·변경 경로 필터·배포 커밋부터 대조한다.
- **빌드 실패:** 실제 오류 로그·실제 입력 파일·출력 디렉터리·필수 에셋·의존성을 점검해 해당 원인만 수정하고 다시 실행한다.
- **배포 실패:** Worker 이름·Wrangler 설정·권한·배포 로그를 확인한다. 존재하지 않는 키·환경변수·가짜 설정으로 성공 처리하지 않는다.
- **웹이 예전 버전:** 커밋·Cloudflare 배포 버전·실제 배포 에셋을 비교하고, CDN/브라우저/Service Worker 캐시를 각각 확인한다. 게임 저장 데이터는 함부로 초기화하지 않는다.
- **웹은 열리는데 게임이 고장남:** JS 런타임 오류, 버튼·터치·초기화·에셋 네트워크 오류를 조사한다.
- **권한/연결 부재:** 연결된 GitHub 도구 등 허용 경로를 먼저 사용한다. 실제 Cloudflare 인증/연결이 필요한 경우에만 **한 번 필요한 최소 조치**를 정확히 안내한다.

## 절대 금지 및 완료 판정
- 자동배포가 구성되어 있다고 **추측**하거나, 문서 작성/파일 저장만 하고 “테스트웹 반영 완료”라고 보고 금지.
- 연결 확인 없이 Cloudflare 계정/사이트/Worker 변경, GitHub Actions 중복배포 추가, 비밀키를 MD에 저장, 예전 HTML로 회귀 금지.
- 배포 실패 때 문제를 숨기고 다른 URL/로컬 테스트/다운로드 파일로 완료 처리 금지.
- **성공 = 올바른 최신 소스 커밋 + 해당 Worker 배포 성공 확인 + 실제 웹에서 변경 확인.** 확인 못 한 단계는 반드시 **미확인** 또는 **실패**라고 표시한다.
- 어떤 MD도 자격 증명·Cloudflare Git 연동을 스스로 만들지 못한다. 최초 연결에 권한이 필요하면 사실대로 보고한다.

## 새 프로젝트
- 중앙 `PROJECT_TEMPLATES/CLOUDFLARE_DEPLOYMENT.md`를 새 저장소 루트의 `CLOUDFLARE_DEPLOYMENT.md`로 복사한다.
- `AGENTS.md` 상단에 본 규칙 필수 참고 문구를 넣는다.
- Worker 이름·공식 공개 URL·배포 입력 파일·Build/Deploy 명령·실제 Git 연동 상태를 먼저 조사해 프로젝트별 문서에 기록한다.
- 프로젝트별 빌드 구조(정적 HTML 복사/Worker JS/토스·MS 별도)는 **유지**한다.
