# SuperSGames 토스용 AIT 원스톱 제작 지침

최종 갱신: 2026-11-08
적용 범위: SuperSGames의 모든 현재 및 신규 게임 프로젝트.
실행 문구: “토스용 만들어줘”, “토스용 AIT 만들어줘”, “토스 출시용 만들어줘” 등.

## 1. 사용자와의 실행 약속

- 사용자는 **처음에 단 한 번 모아진 질문에 답한다**. 이후 담당 AI는 해당 게임의 최종 토스 AIT를 한 번에 제작하고 다운로드 링크를 준다.
- AI는 질문하기 전에 GitHub, 프로젝트 문서, 기존 코드, 토스 설정, 최신 빌드, 최근 대화와 콘솔 자료에서 **스스로 찾을 수 있는 모든 값**을 조사한다. 이미 있는 정보는 묻지 않는다.
- 스스로 못 찾는 ID, 등록 정보, 정책 선택 등 **필수 항목만 한 메시지에 번호를 붙여 한꺼번에 질문한다**. 사용자는 “기존 그대로”, “사용 안 함”, “아직 없음”으로 답할 수 있다.
- 사용자 답변 후 반복 질의 없이 가능한 구현·빌드·검증·최종 파일 전달까지 진행한다. 단 필수 값이 빠졌다면 가짜 값을 넣지 않고, 가능한 테스트 AIT를 먼저 제공하며 운영 빌드 차단 사유를 정확히 적는다.
- **자동 제작은 콘솔 승인·검토·출시를 뜻하지 않는다.** 앱별 승인 상태와 콘솔 등록은 실제 증빙 없이는 주장하지 않고, 사용자의 PC Chrome에서 확인/제출할 일을 최소 단계로 알린다.

## 2. 작업 시작: 질문하기 전에 AI가 직접 확인

1. 정확한 프로젝트 저장소, main 최신 커밋, AGENTS.md, DEVELOPMENT_LOG.md, 게임 설계·밸런스·토스 문서, 기존 AIT 빌드 경로.
2. 사용자가 지정한 실제 마지막 웹(특히 /toss), 배포된 내용, GitHub 최신 원본, 마지막 제공 AIT 차이. **과거 버전으로 임의 회귀하지 않는다**. 출처가 달라 최신 원본을 확정할 수 없으면 그 충돌만 질문.
3. 실제 앱인토스 설정: 앱명/appName, SDK/빌드 버전, 설정 파일, 토스 앱 식별·앱스킴, 테스트/운영 설정값 존재 여부, 사업자·등급·정산·검토/출시 증거.
4. 광고 그룹 ID 및 보상 이벤트, 인앱 결제 SKU/가격/지급량/검증 서버, Game 리더보드 점수/등록, 프로모션 이름·규칙·금액·TEST/운영 코드·검토 상태.
5. UI, 이미지, 진동, 배경음악, 모든 버튼·팝업·저장 키·터치 좌표·화면 규칙, 광고/결제/랭킹/프로모션의 누적 변경. 정상 기능과 기존 유저 기록 유지.

## 3. 한 번에 묻는 통합 질문: 없거나 충돌하는 항목만

아래 전체 목록을 기계적으로 다시 묻지 않는다. 조사해서 찾지 못한 항목만 추려 **단 한 메시지**로 질문한다. 가능하면 각 항목에 토스 콘솔 공식 링크와 메뉴 경로도 붙인다.

1. **앱 정보**: 이 게임의 appName/앱 식별자, 콘솔 등록·승인·검토·출시 상태(모르면 화면 캡처). 프로젝트에 이미 기록된 정보면 생략.
2. **최종 원본**: GitHub·테스트 웹·제공 AIT의 최신 내용이 다를 때 어느 것을 기준으로 할지. 일치하면 묻지 않는다.
3. **광고**: 실제 광고 그룹 ID, 사용할 광고 형태, 어떤 기존 보상에 연결하는지. 기존 설정 있으면 다시 묻지 않는다.
4. **결제**: 등록된 상품 SKU별 판매가격·실제 지급재화, HTTPS 주문검증/중복지급 방지 서버 URL 및 준비 여부. 결제가 없는 게임이면 생략.
5. **랭킹**: 콘솔 게임센터 리더보드 등록·활성화 상태, 게임별 점수 규칙. 이미 코드에 확인되면 생략.
6. **프로모션**: 프로모션별 미션 내용·지급액·기간/일일 한도·콘솔 운영 코드·TEST_ 코드·검토/승인 여부·시작/종료일. 다른 게임 코드를 재사용하지 않는다.
7. **기타 필수 콘솔 정보**: 등급/정산/사업자 확인 상태와, 최종 파일 제작만 할지 업로드까지 원하는지. 기본 요청은 AIT 파일 제작으로 간주한다.
8. API 키·시크릿·비밀 토큰은 채팅에 입력하게 하지 않는다. 필요한 경우 GitHub Secrets 또는 토스 콘솔의 안전한 입력 메뉴를 안내한다.

예시: “기존 코드로 확인되는 값은 채웠습니다. 남은 것만 한 번에 답해주세요. ① appName ② 실제 광고 그룹 ID ③ 하트 상품 SKU와 가격 ④ 리더보드 활성화 여부 ⑤ 프로모션 운영/테스트 코드와 승인 상태. 안 쓰는 항목은 ‘사용 안 함’, 아직 없는 정보는 ‘미등록’이라고 써주세요. 이 답변을 받은 뒤 AIT 제작까지 진행합니다.”

## 4. 질문 답변 이후 담당 AI의 자동 실행 순서

1. **최신 원본 고정**: GitHub 커밋과 배포 웹을 비교해 실제 최신 게임을 사용. 다른 작업자의 변경과 사용자 저장 데이터를 보호.
2. **토스 전용 분리**: 기존 MS용 코드·상점·검토 패키지는 변경하지 않고 토스 WebView/AIT를 별도로 구성. iframe 중첩으로 입력·저장소·SDK가 깨지지 않도록 기존 실제 실행 방식을 확인.
3. **앱 설정**: 해당 게임 appName과 SDK 버전을 사용. 최신 공식 문서에 존재하는 API만 연결.
4. **광고 연결**: 공식 광고 로드/표시 및 보상 획득 이벤트를 구분하고 실제 보상 이벤트에서만 한 번 지급. 취소·오류·미시청에는 지급하지 않는다. 테스트 광고 ID와 운영 광고 ID를 혼용하지 않는다.
5. **인앱 결제**: 실제 SKU/가격/재화 수량 동기화. 주문 검증·중복 지급 방지 서버 성공 후에만 지급. 미완료 주문 복구, 환불/재설치/재시도 점검. 운영 검증 서버가 없으면 가짜 성공 응답을 만들지 않는다.
6. **랭킹**: Game.setLeaderboardScore와 Game.openLeaderboard 등 공식 SDK 사용. 점수 제출 성공 확인, 실패 로그/재시도, 실제 리더보드 열기. 콘솔에 없는 랭킹을 코드만으로 있다고 주장하지 않는다.
7. **프로모션**: 토스 SDK 3.x의 Promotion.grantReward 와 isSupported 확인, 이전 SDK면 공식 호환 API 확인. 테스트 AIT는 TEST_ 코드, 운영 AIT는 해당 앱에 승인된 코드만 사용. 조건 충족 시 지급하고 성공 응답 키·실패·보류를 구별. 1인 1회/일일 한도/Asia/Seoul 자정/중복 진입·재시도를 보호. 클라이언트 저장만으로 고가치 중복 지급 방지를 보장하지 않는다.
8. **검증**: JS 문법, 빌드 로그, AIT ZIP 무결성, 버튼/탭/팝업, 터치, 414×896 화면, 최초 실행/회전/복귀/새로고침, 기존 데이터 보존, 광고 보상, 결제 검증/중복 차단, 랭킹 실패 복구, 프로모션 미션·일일 제한·TEST 호출 로그.
9. **AIT 산출**: 우선 테스트용 파일 완성, 실제 운영 설정 전부 확인되면 운영용 최종 AIT도 작성. 테스트용/운영용 파일명 구별, 실제 생성된 다운로드 링크 제공. 필수 운영 값 없으면 운영 빌드 금지하고 테스트 파일과 부족한 항목 제공.
10. **실기기 테스트**: 콘솔에 업로드한 테스트 스킴/QR에서 광고·결제·리더보드·프로모션 호출을 점검. AI가 직접 실기기 테스트 못 했다면 미검증이라고 구분. 확인 없이 “테스트 전부 통과”라고 하지 않는다.
11. **보고/반영**: DEVELOPMENT_LOG.md 누적, GitHub main 변경은 충돌 없이 수행, 배포/콘솔 업로드/승인 상태는 별개로 보고. 사용자가 요청하지 않은 심사 제출·프로모션 운영 전환·결제·비즈월렛 조작은 하지 않는다.

## 5. 냥냥버블팡에서 다른 게임에 **복사할 것과 금지할 것**

재사용: 토스 WebView 직접 실행 구조, 광고 이벤트 브리지, 실제 SKU 검증, Game 랭킹, 프로모션 SDK 호출, 테스트용/운영용 분리, 실기기 검증, 일괄 질문, 최종 AIT 다운로드 흐름.

냥냥버블팡의 예시 프로모션은 “매일 최초 정상 접속 1원” 및 “하루 5판 정상 완료 시 3원(승패 무관)”이다. **이것은 다른 게임에 자동 도입할 기본 정책이 아니다.** 다른 게임에는 해당 게임의 콘솔에 실제 등록·검토된 미션과 코드만 적용한다. 5판 카운트는 정상 완료만 계산하며, 오늘 테스트 전 이미 플레이한 회차가 처리되지 않았더라도 테스트를 위해 운영 저장 데이터를 초기화하지 않는다.

다른 게임으로 이동할 때 **복사 금지**: 냥냥버블팡 appName, 광고 그룹 ID, 상품 SKU·가격·보유하트 지급량, 리더보드 식별/점수 규칙, 프로모션 운영 코드·TEST 코드, 승인 내역, 사용자 저장 키, 이미지 및 게임 UI. 기존 토스 앱에서 승인받은 내용이 다른 앱에 자동 승인되는 것은 아니다.

## 6. 정책 및 검토 보호

- 게임 결과(점수·승패·등수)에 연동된 포인트 지급과 게임의 확률형·랜덤 포인트 프로모션은 공식 금지 유형. 게임 5판 참여와 같은 행위형 미션도 콘솔에 **정확히 그 조건으로 등록·검토한 경우에만** 활성화한다.
- 프로모션은 사전 검토가 필요하며, 테스트 코드는 실제 지급 예산을 쓰지 않고 호출을 검증하는 수단이다. TEST_ 코드 호출 성공, 실제 운영 코드 승인, 실제 앱 공개 출시는 서로 다른 단계.
- SDK 지원 버전 및 API는 제작할 때 공식 문서 재확인. 토스앱 5.232.0 이상 지원 프로모션 API는 SDK 3.x에서 Promotion.grantReward({ promotionCode, amount })이다.
- 사용자에게 비밀 키 공개를 요청하지 말고 저장소에 넣지 않는다. 외부 콘솔 접속/승인/정식 출시가 기술적으로 불가능하면 명확히 구분해 남긴다.

## 7. 새 프로젝트에 자동 설치

- 새 저장소 루트에 TOSS_AUTOMATION.md 참조 문서를 넣고 AGENTS.md에 “토스용 만들어줘” 트리거를 기록한다.
- 이 중앙 원본은 SuperSGames/SuperSGames의 PROJECT_TEMPLATES/TOSS_AUTOMATION.md 에 유지한다.
- 새 게임별 환경 설정/코드는 따로 보관한다. 중앙 지침만 공통이며 앱별 실식별자·상품·승인은 재사용하지 않는다.
