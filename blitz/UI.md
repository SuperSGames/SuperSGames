# UI.md — SuperSGames 공통 UI 원화·에셋 제작 절대 규칙

> 버전 3.0 / 2026-11-13 / 모든 기존·신규 SuperSGames 게임 적용
>
> **가장 중요한 원칙: 이미지에는 영구히 변하지 않는 장식·형태만 그리고, 숫자·문구·게이지·알림 등 게임 상태는 프로그램의 독립 레이어로 표현한다.**
>
> 본 규칙은 UI 시안, 이미지 생성, 스프라이트 시트, 추출, 크롭, 웹 게임 연동, AIT/MS 빌드 모두에 적용한다. 사용자의 최신 명시적 지시를 우선하되, 오래된 예시·프롬프트·기획과 충돌하면 본 문서의 금지 규칙을 따른다. 기존 정상 UI/게임을 요청 없이 일괄 교체하라는 뜻은 아니다.



## [최우선 v3.0] 창 위의 모든 요소는 별도 원화·레이어로 제작 (2026-11-13)

> **최우선 절대 원칙:** 스프라이트 시트에서는 부품끼리 겹치지 않고, 실제 게임 화면에서만 프로그램이 레이어를 겹쳐 조립한다. 설정창·결과창·상점·HUD·미션·랭킹·하단바를 완성 화면 한 장으로 합성하여 그리거나 사용하지 않는다. 이전 v2.0·v1.0과 충돌하면 이 규칙 우선.

### 1. 무엇을 창 바탕에 그릴 수 있나

- 빈 창과 패널에는 **바탕 자체의 표면 재질, 색, 테두리, 패널에 속한 불변 모서리 형상**만 그린다. 정면에 별개 물체로 올려놓는 요소는 장식이어도 포함하지 않는다.
- **창 위에 얹힌 모든 개체는 무조건 독립 에셋·독립 레이어**로 그린다. 제목 리본, 꽃, 별, 왕관, 캐릭터 얼굴, 닫기 X, 하트/코인/보석 아이콘, 버튼, 탭, 스위치, 상점 상품, 결과 별, 말풍선, 배지, 손가락·화살표, 반짝임 등이 해당된다.
- **장식이 영구적으로 보이더라도** 창 위에 얹힌 부품처럼 보인다면 원화에 합치지 않고 별도 셀에 그린다. 사용자가 고정한 기존 완성 로고·일러스트의 보존은 예외이나 새 UI 패널을 통짜로 만들라는 뜻이 아니다.
- 그림 표면의 나뭇결, 재질감, 선천적인 테두리처럼 분리해도 별도 물체가 아닌 **바탕 자체의 질감만** 바탕에 포함 가능하다.
- 글자·숫자·가격·시간·스테이지·설명·안내·제목·점수·알림의 개수·ON/OFF 글자는 코드에서 텍스트로 덧씌운다. 그림에 굽지 않는다.
- 게이지의 현재 채움, 별 획득 개수, 잠금·선택·완료 표시, 알림의 NEW/!/빨간 점은 코드가 해당 상태일 때만 별도 에셋·레이어로 나타내야 한다.
- 창, 제목판, 버튼, 아이콘, 수치, 효과 중 하나를 숨겨도 나머지 원화가 훼손되지 않아야 한다.

### 2. 화면별 반드시 분리할 요소

| 최종 화면 | 별도 원화 | 실제 게임 코드가 위에 올릴 것 |
|---|---|---|
| 게임 시작/메인 | 빈 화면판, 로고, 장식, 버튼판, 버튼 심볼 각각 | 메뉴 텍스트·버튼 동작·상태 |
| 설정창 | 빈 창, 독립 제목 리본, 옵션별 아이콘, 스위치 ON, 스위치 OFF, 닫기 X | 제목·옵션명·현재 ON/OFF·터치 |
| 클리어/실패창 | 빈 결과판, 별 empty/earned, 고양이, 꽃, 버튼판 등 모두 개별 | 성공/실패 제목·점수·실제 획득 별 수·다음 동작 |
| HUD/수량바 | 빈 바, 하트/보석/코인 원화, 독립 추가 버튼 | 현재 수량·타이머·스테이지·게이지 상태 |
| HP/스킬바 | 빈 프레임, 별도의 채움 원화, 독립 아이콘·끝 장식 | 현재 비율만큼 이미지 클리핑·수치 표시 |
| 편지/선물 | 알림 없는 편지/선물 원화, 별도 알림 그림 | 알림이 있을 때만 !·빨간 점·NEW 표시 |
| 상점/미션/랭킹 | 빈 카드·빈 탭·상품 원화·버튼판·아이콘 각각 | 상품명·가격·수량·순위·진행·구매 가능 상태 |
| 튜토리얼 | 빈 말풍선, 독립 화살표/손가락 원화 | 상황별 안내 글씨·표시 시점·동작 |
| 하단 내비 | 빈 고정바, 독립 탭 기본/선택, 독립 고정 아이콘 | 현재 선택된 탭만 아래로 이동·터치 판정 |

### 3. 게임 코드 레이어 조립 방식

1. 화면을 구성하는 독립 요소를 각각 크롭/로드해 **배경 → 빈 창·바탕 → 리본·꽃 같은 독립 장식 → 빈 슬롯·바 → 버튼/스위치 상태판 → 아이콘 → 코드 텍스트·현재 수치 → 알림·선택·완료 표시 → 일시적 이펙트**의 순서로 필요할 때 조합한다. 실제 요구에 따라 깊이 순서는 조정할 수 있다.
2. **이미지 파일 단계에서는 원화끼리 절대 겹치지 않는다.** 꽃이 창 테두리에 걸쳐 보이도록 원한다면 꽃과 창은 별도 파일/셀이고 게임에서만 좌표를 겹친다. 이는 스프라이트 시트의 셀 침범 금지와 모순되지 않는다.
3. 창이 움직이면 창 기준의 독립 요소도 동일한 부모 좌표 또는 앵커를 기준으로 따라간다. 414×896 고정 뷰포트 및 최상위 프레임만 스케일 규칙 유지.
4. 클릭 가능한 각 버튼·토글·닫기 아이콘은 해당 이벤트가 실제로 작동해야 한다. 장식 이미지가 터치를 가로채지 않도록 클릭 대상과 비클릭 오버레이를 구분한다.
5. 각 상태 이미지는 다른 셀에 독립 배치한다. 실제 ON/OFF 토글은 **양쪽 모두**, 클릭 버튼은 **normal/pressed**, 필요한 경우에만 selected/disabled. 한 셀에 서로 다른 상태를 합치지 않는다.
6. UI 자산 목록에는 각 개체의 **asset_id / 역할 / 부모 창 / 코드 레이어 순서 / 상태 종류 / 표시 조건 / 배치 기준점 / 크롭 좌표**를 기록한다. 실제 게임에 없는 요소는 추가 금지.
7. 기존 승인된 그림·코드·저장 데이터는 사용자 요청 없이 대체하거나 전체 구조를 바꾸지 않는다.

- [ ] 시트에서는 겹침 0이고 **게임 화면에서만** 의도에 따라 레이어를 겹치는가?

위 항목 중 하나라도 실패하면 사용자에게 완성 UI로 전달하지 않는다.

## [최우선 v2.0] 실제 사용 가능 UI 에셋만 제작 — 2026-11-13

> **이 절이 과거 예제 그림·프롬프트·아래 v1 규칙과 충돌하면 v2.0이 우선한다.** UI 원화를 만드는 목적은 완성된 게임 화면을 한 장으로 그리는 것이 아니라, **코드에서 상태·문자·수치를 독립적으로 조합할 수 있는 에셋 원본**을 만드는 것이다.

### A. 필요한 에셋을 먼저 조사하고, 없는 기능은 그리지 않는다

1. 현재 프로젝트의 **검증 가능한 최신 소스·확정 UI 기획**을 먼저 확인한다. 기획 미확정 시 임의로 새 기능을 상상하지 않는다.
2. 제작 전에 자산 목록을 먼저 확정한다. 각 항목은 **asset_id / 실제 사용 화면 / 프로그램에서 수행하는 기능 / 기본 그림 / 필요한 상태별 이미지 / 별도 동적 오버레이 / 크롭 크기**를 기록한다.
3. **게임에 없는 버튼·재화·보상·장식·배지·알림을 그리지 않는다.** 섞기·힌트·광고·랭킹·운세 등의 이름이 예시 프롬프트에 있다고 해서 실제 기능이 되는 것이 아니다. 현재 게임에 있거나 사용자가 추가를 승인한 경우에만 그린다.
4. 필요한 버튼을 빠뜨리고 로고·장식·중복 백판으로 셀을 채우지 않는다. 셀이 모자라면 **시트를 추가한다.** 실제 없는 엉뚱한 아이콘으로 채우지 않는다.
5. 이미 사용자 승인한 로고·화투패·아이콘·버튼·패널·그림은 재사용한다. **기존 승인 에셋을 임의로 다시 그리거나 디자인을 바꾸지 않는다.**
6. 시안/스크린샷을 그대로 복제하지 않는다. 스타일 참고와 실제 추출용 에셋 납품을 명확히 구분한다.

### B. 사용자 예시 이미지에서 반복되는 잘못된 결과와 수정 기준

| 잘못된 결과 | 올바르게 그릴 원화 / 코드가 그릴 내용 |
|---|---|
| 버튼에 ‘시작’, ‘홈’, ‘섞기’, ‘힌트’, ‘다음’, ‘취소’, ‘확인’, ‘다시하기’ 등의 글자가 박혀 있음 | **글자 없는 버튼 바탕**. 버튼명·가격·횟수는 프로그램 텍스트. 상시 고정 심볼은 독립 아이콘으로 분리. |
| 시작·설정·클리어·실패 팝업 판 안에 제목, 설명, 버튼, 결과, 별까지 합쳐져 있음 | **빈 팝업 판 1개** + 필요한 장식 + 독립 버튼판 + 코드 제목·설명·숫자·결과. 화면 전체를 완성 시안처럼 굽지 않는다. |
| 설정창의 소리·음악·진동 스위치가 모두 녹색 ON인 한 장의 그림 | **빈 설정창** + 실제 동작하는 옵션마다 독립 ON / OFF 상태 이미지 + 코드 상태값. ON만 제작 금지. |
| ON/OFF를 텍스트까지 포함해 한 그림에 그리거나 한 셀에 두 개를 겹침 | ON과 OFF를 **각각 독립 셀에 1개씩**, 동일 크기·정렬·터치 범위로 제작. 손잡이의 위치/색/모양으로 구분, ON/OFF 글씨는 코드 표시. |
| 별 3개가 모두 획득한 채로 고정된 클리어창 | 필요할 때만 빈 별/획득 별 아이콘을 각각 따로 만들고 **실제 획득 개수**를 코드에서 조합. |
| 하트·코인·보석 수량판에 값·충전량·+버튼을 통째로 합침 | **재화 아이콘 / 빈 수량판 / 독립 + 버튼**을 기능별로 분리하고 수치는 코드로 표시. |
| HP·스킬·진행 게이지가 이미 일정 비율 채워져 있음 | **빈 게이지 테두리**와 별도 **채움 원화**. 현재 비율은 코드의 이미지 클리핑/마스킹으로 계산. |
| 편지·선물 위 느낌표, NEW, 빨간 알림 점이 기본 그림에 있음 | 깨끗한 기본 아이콘만 제작. 조건부 느낌표·알림점은 코드의 독립 오버레이. |
| 말풍선에 ‘같은 그림 두 장…’ 등 튜토리얼/설명 문구가 박혀 있음 | 빈 말풍선만 제작. 모든 한글 안내 문구는 코드로 표시. |
| 시트에 ‘이용 횟수는 따로…’ 같은 설명문·격자 안내선·회색 바탕이 있음 | **납품할 시트에는 설명 글자와 바탕/격자 자체가 없어야 한다.** 설명과 좌표는 별도 MD/표로 기록. |
| 길쭉한 장식 바·게이지·하단바를 작은 버튼 시트에 섞고 비율이 찌그러짐 | 긴 바는 **별도 가로형 시트**를 만든다. 크롭 가능하도록 각각 독립, 내부 숫자/표시는 없음. |

**주의:** 게임 로고처럼 사용자 승인한 영구 글씨는 해당 로고 안에서 허용할 수 있다. 상시 도움말 물음표(?) 버튼의 **고정 심볼**, 닫기(X) 심볼, 재화의 **고정 + 구매 버튼**은 실제로 기능이 있을 때 정적 아이콘으로 허용한다. 편지 위 알림 물음표나 상황에 따라 바뀌는 체크·NEW·숫자는 그런 예외가 아니다.

### C. ON/OFF 및 버튼 상태 필수 규칙

- 실제 게임에 존재하는 켜기/끄기 옵션(예: 효과음·배경음악·진동·연출)에 대해서는 **ON 이미지와 OFF 이미지 둘 다** 제작한다. 옵션 자체가 없으면 추가하지 않는다.
- 별도 그림의 기본 자산명: toggle_on / toggle_off. **OFF도 독립적으로 그려진 완성 이미지**여야 한다. 단순히 ON 그림을 회색 투명으로 처리하고 OFF 제작을 생략하지 않는다.
- 스위치는 양쪽 상태에서 **같은 이미지 캔버스 크기·기준점·터치영역**, 뚜렷이 다른 손잡이 위치(왼쪽/오른쪽)와 명암/색 차이를 가진다.
- **이미지 안에 ON / OFF 글자를 굽지 않는다.** 실제 화면에서 ON/OFF를 글자로 보여주고 싶다면 앱이 현재 설정값으로 프로그램 텍스트를 출력한다.
- 인터랙션 가능한 일반 버튼은 **normal, pressed** 이미지를 원칙으로 한다. disabled, selected, locked는 해당 게임에서 실제 사용할 때만 추가한다. 상태별 원화의 크기·정렬·터치 기준점은 통일한다.
- 비활성 상태가 별도 디자인을 요구할 때는 disabled 이미지로 제작한다. 별도 비활성 그림이 필요하지 않은 UI는 코드 상태로 처리한다. 의미 없는 모든 상태를 형식적으로 늘리지 않는다.
- 하단 탭은 현재 게임에 존재하는 탭만 그리고, 필요 시 normal/selected 두 이미지를 독립 제작한다. **선택된 탭만 내려가고 다른 탭 위치는 유지**하는 기존 고정 하단바 정책과 일치시킨다.
- 동일한 아이콘이 스위치·상태판·팝업과 붙어서 한 에셋으로 합쳐지면 안 된다. 상태는 **코드가 해당 이미지 하나를 교체하여 표현**한다.

### D. 완성된 팝업을 그리지 말고 모듈 단위로 분리한다

**1셀 = 하나의 독립 크롭 가능 UI 구성 요소 1개**를 기본으로 한다.

- 빈 창(panel_blank)에는 외곽 프레임과 영구 장식만. 제목·별·현재 값·문구·확인 버튼을 넣지 않는다.
- 버튼판(button_normal / button_pressed)은 **글씨 없는 판 하나**. 아이콘이 반드시 붙어 있어야 하는 확정 디자인을 제외하면 고정 심볼도 별도 PNG로 관리.
- 고정 아이콘(icon_name)은 현재 게임에 실제로 등장하는 상시 심볼만.
- 바(bar_frame)는 **빈 프레임**, bar_fill은 **별도 채움 이미지**. 코드는 실제 양을 클리핑해서 표시한다.
- 값·상태 알림(badge_notification 등)은 **필요한 순간만 나타나는 별도 오버레이**, 기본 그림에 포함 금지.
- 클리어 별은 필요한 게임에서만 star_empty / star_earned 각 한 개씩 준비하고 상태별로 반복 배치. 처음부터 전부 금색인 3성 결과를 고정하지 않는다.
- 긴 가로바·하단바·상태 표시판은 아이콘/일반 버튼과 **시트 분리**. 가로 길이를 유지하고 화면에 맞게 이미지 자체를 억지로 늘이지 않는다.
- 사용자가 승인한 완전 고정 로고·캐릭터 원화는 예외적으로 하나의 원화일 수 있으나, 그 안에 버튼·타이머·팝업 가변 내용이 섞여 있으면 별도 에셋으로 분리한다.

### E. 최종 PNG 스프라이트 규격과 파일 배치

1. 같은 비율과 용도의 이미지끼리 묶어 **아이콘 시트 / 버튼·상태 시트 / 가로형 바 시트 / 대형 패널 시트**로 구분한다. 게임에 필요하지 않은 카테고리는 만들지 않는다.
2. 별도 셀 크기 지시가 없으면 **256×256px**. R×C 시트 전체 크기는 **(열 C×셀 너비) × (행 R×셀 높이)**. 5×5는 정확히 **1280×1280px**. 사용자가 다른 셀 크기를 명시했다면 그것을 최우선으로 지킨다.
3. 가로형 바는 별도 시트에서 **명시한 가로형 셀 크기**를 사용해도 된다(예시: 512×128px). 사용자가 고정한 셀 규격을 임의로 변경하지 않는다.
4. 그림·꽃·손·귀·그림자·빛·반투명/안티앨리어싱 픽셀까지 **오직 자신의 셀 내부**. 다른 셀과 겹침·침범·잘림 0. 모든 셀 바깥 2픽셀 띠는 alpha=0.
5. **최종 UI 시트는 투명 PNG RGBA**. 전체 바탕·타일·체크무늬·흰/검정/회색 배경·가이드·외곽선·설명 글자·번호표는 넣지 않는다. 실제 PNG alpha를 검사한다.
6. 각 셀은 직사각형으로 정확히 크롭해도 **단독 에셋이 완성**돼야 한다. 한 셀에 두 상태를 나란히 넣거나, 여러 개의 다른 에셋을 겹쳐 그리지 않는다.
7. 하나의 시트에 모두 들어가지 않으면 **여러 시트**를 납품한다. 칸이 모자라서 필요한 에셋을 빼먹거나, 남는 칸을 의미 없는 그림으로 채우지 않는다. 지정한 R×C를 맞추기 위해 누락/중복/합성을 해서는 안 된다.
8. 각 시트는 외부 문서에 **시트명 / 행×열 / 셀 너비×높이 / 총 픽셀 / (행,열) → asset_id와 상태**를 기록한다. 격자 번호와 이름은 **이미지에 직접 그리지 않는다.**
9. 기본적으로 시트로 납품하고 개별 파일은 사용자가 명시 요청한 경우만 만든다.
10. **Pillow로 PNG/RGBA·정확한 픽셀·셀 외곽 2px 알파를 실제 검사**하고, 셀별로 크롭해서 상태 누락·글자 박힘·가짜 배경·셀 겹침을 육안 확인한다. **하나라도 실패하면 납품하지 않는다.**

## 1. 그림에 미리 넣는 것을 절대 금지하는 것

- 모든 가변 숫자: 스테이지·레벨·경험치·랭킹·점수·코인·보석·하트·아이템·이동 횟수·시간·가격·할인율·퍼센트·보상 수량·날짜·카운트다운 등.
- HP·체력·마나·스킬·구조·경험치 등의 게이지에서 **채워진 부분, 현재 잔량, 진행률, 조건부 색**. **빈 프레임**은 그릴 수 있다.
- 버튼명·가변 한글·가격·설명·선택지·스토리 대사·임무 내용·상점 라벨·오류 안내. 버튼 제목이 현재 고정이어도 **기본 버튼 PNG에는 글자를 그리지 않는다**.
- 편지·선물·보상상자·우편함 위의 **느낌표(!), 물음표(?), NEW, 빨간 점, 미확인 숫자, 완료 체크, 알림 배지**.
- 선택 테두리·강화 가능 표시·장착 중·수령완료·잠금/해제 표식·튜토리얼 화살표·성공/실패 효과 등 나타났다 사라지는 표현.
- 테스트 데이터·예제 텍스트와 숫자도 금지: 0, 1, 99, 100%, 00:00, +1, 1,100원, !, NEW 등 **미리 채워 놓고 게임에서 덮어쓰는 방식 자체를 금지**.
- 장식처럼 보이더라도 **게임 상태에 따라 생성·변경·소멸한다면 동적 정보**다. 지금 항상 보여도 미래에 바뀔 가능성이 있으면 분리한다.
- UI의 빈 공간이 허전하다는 이유로 숫자, 글씨, 느낌표, 배지, 임의 장식을 채우지 않는다.

**예외:** 불변 로고나 게임 세계관 속 실제 간판·원화의 일부인 인쇄물은 **그 개별 에셋에 대해 사용자가 명시적으로 허락한 경우에만** 그린다. 버튼명·숫자·상태 정보는 이 예외에 넣지 않는다.

## 3. UI 원화 디자인 방법

- 실제로 그린 PNG/WebP 래스터 아트를 사용한다. 기존 승인된 원화의 분위기·모양·색상·비율을 함부로 바꾸지 않는다.
- **SVG 제작 전면 금지:** SVG 파일, 인라인 SVG, SVG의 path/rect/circle 등, SVG→PNG/WebP 변환 우회, SVG 자동 생성 패키지를 원화에 쓰지 않는다.
- **도형 조립 아트 금지:** CSS 사각형·원·그라디언트·그림자·가상 요소 및 Canvas 기하 도형을 조합해 아이콘·캐릭터·배경·버튼 그림처럼 만드는 대체 제작을 금지한다.
- HTML/CSS/Canvas의 **레이아웃·위치·텍스트·실제 이미지 클리핑·상태 애니메이션·터치 기능**은 가능하다. 그림 그리기 용도가 아니다.
- 버튼은 눌리는 버튼답게, 창은 창답게 독립적으로 디자인한다. 불필요한 문양·장식은 최소화하고 데이터 영역을 확보한다.
- 버튼 기본/눌림/선택/비활성 등 필요한 상태는 **각 상태를 별개 그림**으로 만들되, 크기·기준점·터치 영역이 동일하게 맞도록 한다.
- 명령받지 않은 번쩍임·별·배지·알림·숫자·워터마크·설명 텍스트를 추가하지 않는다.
- 게임의 414×896 논리 좌표, 상단 안전 영역, 하단 고정바 및 **최상위 프레임만 스케일** 원칙을 유지한다. 그림 제작 이유로 내부를 임의 반응형으로 바꾸지 않는다.

## 4. 투명 배경·납품 포맷 강제

- **아이콘·버튼·패널·테두리·상태 이미지·효과·UI 스프라이트 시트는 PNG RGBA**, 그림 외 영역은 반드시 **alpha=0 완전 투명**이다.
- 흰색/검정/회색/색상 바탕, 체크무늬 배경을 실제 이미지 픽셀로 넣지 않는다. 가짜 투명 배경 금지.
- 단일 요소 밖에 배경 패턴·격자선·안내선·번호표·캔버스 테두리·반투명 잔재·노이즈·워터마크를 넣지 않는다.
- 실제 원화 내부의 정적인 질감과 고정 음영은 가능하다. 모든 그림자·광원·장식까지 **해당 에셋/셀 내부**에 완전히 담는다.
- **전체 화면의 전용 배경 일러스트**를 사용자가 별도로 요청한 경우에만 불투명 배경 파일을 허용한다. UI 에셋 시트와 하나로 합치지 않는다.
- 미리보기 스크린샷이나 여러 아이콘이 겹친 합성 시안은 게임에서 **그대로 잘라 쓸 수 있는 원본 에셋**이 아니다.

## 5. R행 × C열 스프라이트 시트: 반드시 픽셀 검증

1. 행 R, 열 C를 정확하게 지키며 **R×C개의 독립 셀**을 만든다. 셀 추가·누락·임의 합침 금지.
2. 셀 크기 지시가 없으면 **256×256px**. 별도 지시가 있으면 해당 픽셀 크기를 따른다.
3. 전체 캔버스 = **(열 C × 셀 너비) × (행 R × 셀 높이)** px. 정수여야 한다. 예: **5×5 셀 256 → 1280×1280px**.
4. 각 오브젝트는 자신의 셀에만 배치한다. 본체·팔·손·귀·꼬리·장식·그림자·빛·이펙트·반투명 픽셀까지 **셀 경계를 단 1픽셀도 넘으면 불합격**.
5. **모든 셀의 바깥쪽 상하좌우 각각 2픽셀은 alpha=0 정확히 완전 투명**. 셀 가장자리에서 부드러운 반투명조차 허용하지 않는다.
6. 각 셀 오브젝트는 비율을 보존한 채 충분한 내부 여백을 둔다. 지나치게 커서 잘리면 **축소하고 중앙/지정 기준점으로 재배치**한다.
7. 셀 사이 격자선/구분선/외곽선/임의 픽셀을 **절대 그리지 않는다**. 전체 배경은 완전히 투명하며 개별 셀은 정확한 사각형으로 크롭 가능해야 한다.
8. 상태별 버튼·동일 계열 아이콘은 크기·축·기준점이 일관되도록 정렬한다. 오브젝트 두 개를 한 셀에 겹치거나 반쯤 넘겨 넣지 않는다.
9. 사용자가 별도 요구하지 않으면 **개별 이미지 파일 여러 개를 만들지 말고 최종 PNG 시트 1장만 제공**한다.
10. 이미지 생성 결과의 크기와 알파를 **절대 믿지 말고 실제 파일의 픽셀을 검사**한다. 실패 시 정규화·축소·재배치 후 재검증한다. 한 칸이라도 불합격이면 완성본으로 전달하지 않는다.

### 검사 방법 (Pillow로 실제 파일 검사)

- PNG 파일 여부, 이미지 모드 RGBA, 정확한 시트 가로·세로 픽셀을 확인한다.
- 모든 셀을 R×C 순회하면서 네 가장자리 2픽셀의 **alpha가 하나도 빠짐없이 0**인지 확인한다.
- 빈 셀이 없는지, 그림의 불투명/반투명 픽셀이 2px 경계 내로 침범하지 않았는지 확인한다.
- PNG 원본을 셀별 실제 크기로 **가상 크롭해** 서로 겹치거나 잘리지 않았는지 육안 검수한다.
- **시각 검수도 필수:** 숫자·글씨·!·NEW·체력바 채움·상태 체크가 없는지, 정확히 요청한 다른 종류의 그림이 모두 있는지 확인한다.
- 코드 기반 픽셀 검사는 보이는 의미나 이미지 내용까지 보장하지 못한다. **정확한 파일 검사 + 내용 검수 두 가지 모두 통과**해야 합격이다.

### 실제 자동 검수에 사용할 수 있는 Python 예시

~~~python
from PIL import Image

def verify_ui_sheet(path, rows, cols, cell_width=256, cell_height=256):
    image = Image.open(path)
    expected = (cols * cell_width, rows * cell_height)
    assert image.format == "PNG", f"PNG 파일 아님: {image.format}"
    assert image.mode == "RGBA", f"RGBA 형식 아님: {image.mode}"
    assert image.size == expected, f"실제 {image.size}, 필요 {expected}"
    assert cell_width > 4 and cell_height > 4, "셀 크기가 너무 작습니다."
    alpha = image.getchannel("A")
    for r in range(rows):
        for c in range(cols):
            x, y = c * cell_width, r * cell_height
            a = alpha.crop((x, y, x + cell_width, y + cell_height))
            boundaries = [
                a.crop((0, 0, 2, cell_height)),
                a.crop((cell_width-2, 0, cell_width, cell_height)),
                a.crop((0, 0, cell_width, 2)),
                a.crop((0, cell_height-2, cell_width, cell_height)),
            ]
            if any(region.getbbox() is not None for region in boundaries):
                raise ValueError(f"셀 {r+1}행 {c+1}열: 2px 경계 alpha 불량")
            if a.getbbox() is None:
                raise ValueError(f"셀 {r+1}행 {c+1}열: 빈 셀")
    print(f"PASS: {rows}×{cols}, {expected}, RGBA, 셀 경계 투명")

# verify_ui_sheet("ui_sheet.png", rows=5, cols=5)
~~~

## 6. 원화 생성 프롬프트 첫머리에 넣는 고정 지시

> "UI 원화는 변하지 않는 그림·프레임·버튼판만 제작한다. 숫자, 시간, 가격, 레벨, 스테이지, HP/경험치/스킬 게이지의 채움, 버튼 위 가변 글자, 알림 느낌표(!)·빨간 점·NEW·미수령 수량·선택/완료 체크 등 모든 상태 정보는 절대 그림에 포함하지 않는다. 프로그램의 별도 레이어에서 표시한다. 배경은 완전 투명한 PNG RGBA, 요청한 R×C 격자와 정확한 픽셀 크기, 셀 바깥 2px alpha=0, 모든 오브젝트·그림자·반투명 효과는 자신의 셀 안에만 놓는다. 격자선·번호·배경은 그리지 않는다. SVG/CSS/Canvas 도형 조립 대신 실제 그린 원화를 사용한다. 최종 파일의 실제 픽셀을 검사해 실패하면 다시 제작한다."
